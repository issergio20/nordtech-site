# Архитектура: новый nordtech.su (пересборка сайта НОРД на MODX)

Основа: `replica/recon.md`, `replica/features.csv`. Схема собственных таблиц: `replica/schema.sql`.
Решение по стеку (2026-11-10): **остаёмся на MODX**. Клиент уже знает админку, каталог и URL сохраняются без миграции данных, а пересборка сводится к новой вёрстке, чистке данных и доделке пустых разделов.

## Стек

| слой | выбор | почему |
| --- | --- | --- |
| CMS | MODX Revolution 3.x (последняя стабильная), PHP 8.2+ | обновляем текущую установку на месте: ID ресурсов, URI и товары остаются, SEO не страдает |
| шаблоны | pdoTools 3 + Fenom, вёрстка с нуля по токенам из replica-design | Fenom быстрее и чище чанков MODX; вёрстку заново, а не латать старую |
| стили и скрипты | SCSS + токены (CSS-переменные), сборка Vite, ванильный JS; Swiper (карусели), Fancybox 5 (окна) | без jQuery: на сайте 4 интерактивных виджета, фреймворк не нужен |
| каталог | miniShop2 4.x: msCategory, msProduct, бренды (msVendor), характеристики (ms2 Options) | уже на сайте; характеристики привязываются к разделам — у насосов и погрузчиков разные наборы |
| фильтры и поиск | mSearch2 (mFilter2 + поиск с морфологией) | уже на сайте; морфология русского языка из коробки. Сломанный фильтр чиним настройкой, а не заменой |
| формы | FetchIt (AJAX) + FormIt + свой хук `nordLead` | FetchIt уже стоит; хук пишет заявку в `modx_nord_leads`, выбирает филиал и отправляет уведомления |
| повторяющиеся блоки | ClientConfig (телефон, соцсети, реквизиты) + MIGX (счётчики, этапы, услуги, FAQ, партнёры) | клиент правит без программиста; отдельные таблицы не нужны |
| база данных | MariaDB 10.6+ (или MySQL 8), InnoDB, utf8mb4 | стандарт для MODX |
| авторизация | только менеджеры в админке MODX, двухфакторная авторизация (2FA) включена | у посетителей нет личных кабинетов |
| платежи | нет | цены по запросу, продажа через заявку и договор |
| почта | SMTP Яндекс 360 / Unisender Go с доменного ящика (`@nordtech.su`) + SPF, DKIM, DMARC | письма с mail.ru от имени сайта уходят в спам; ПДн остаются в РФ |
| уведомления | Telegram Bot API (официальный), чат на каждый филиал | менеджер видит заявку за секунды, а не когда откроет почту |
| антиспам | Yandex SmartCaptcha (невидимый режим) + скрытое поле-ловушка | российский сервис, без reCAPTCHA |
| фоновые задачи | cron на сервере → CLI-скрипты MODX | повторная отправка уведомлений, очистка ПДн, бэкапы |
| файлы | локально на сервере, WebP через pThumb/phpThumbOn, отложенная загрузка | фото техники — основной вес страниц |
| хостинг | VPS в РФ (Timeweb Cloud / Selectel), nginx + PHP-FPM, Let's Encrypt; staging на поддомене | 152-ФЗ; staging нужен для обновления до MODX 3 без риска для прода |
| аналитика | Яндекс Метрика (цели на каждую форму) + Вебмастер | для replica-analyst и SEO |

Одна база, один сервер, никаких микросервисов.

## Каталог: структура данных

Разделы и товары — ресурсы MODX (`modx_site_content`). Деревья URL не меняем: `/katalog/{раздел}/{подраздел}/{товар}`.

**Поля товара (miniShop2 + опции):**

| что | где хранится | правило |
| --- | --- | --- |
| название, описание, SEO | ресурс | описание обязательно перед публикацией (см. «Чистка данных») |
| бренд | `vendor` → `modx_ms2_vendors` | для фильтра по бренду |
| «Топ-10» на главной | `popular = 1` | вывод: `msProducts` с `popular=1`, не больше 10, сортировка по `menuindex` |
| наличие | опция `availability`: `in_stock` / `on_order` | плашка «В наличии» / «Под заказ» |
| «Максимальная комплектация» | опция `max_config` (checkbox) | метка на карточке |
| цена | `price` = 0, не выводится | поле оставляем на случай, если клиент решит показывать цены «от» |
| фото | `modx_ms2_product_files` | первая — превью; минимум 1 |

**Характеристики (ms2 Options), набор на раздел «Спецтехника»** — ключ, тип, единица:
`series` (text), `engine_type` (text), `fuel` (combo), `power_hp` (number, л.с.), `engine_volume_l` (number, л), `drive` (combo), `dimensions_mm` (text Д×Ш×В), `speed_kmh` (number), `wheelbase_mm` (number), `clearance_mm` (number), `tire_size` (text), `transmission` (text), `axles` (number), `load_capacity_kg` (number), `operating_weight_kg` (number), `country` (combo), `warranty` (text).
Первые 3 опции раздела (по `rank`) показываются на карточке в списке.
Свои наборы для разделов «Насосы» (производительность м³/ч, напор м, привод), «ДГУ» (мощность кВт/кВА, двигатель, исполнение), «Колёса» (размер, тип), «Аксессуары» (размер, совместимость) — согласовать с клиентом, когда появятся товары.

**Подраздел «Фронтальные погрузчики»** в «Спецтехнике»: сейчас 5 погрузчиков Lonking лежат в корне раздела и не попадают ни в одну вкладку. Создаём подраздел и переносим, старые URL — 301 на новые.

## Схема собственных таблиц

Таблиц: 2 своих (`modx_nord_branches`, `modx_nord_leads`) + штатные таблицы MODX и miniShop2.
Права доступа: проверки на уровне приложения. Заявки видны только в админке через свой CMP «Заявки», доступ у группы менеджеров MODX (`nord_leads_view` — политика доступа). Публичных запросов на чтение к этим таблицам нет.

Полный SQL — `replica/schema.sql`. Главное:

- `modx_nord_leads.submit_token` — уникальный UUID, его генерирует форма при открытии: двойной клик или повтор запроса не создаёт вторую заявку.
- `product_title` — снимок названия: товар могут переименовать или снять, а в заявке должно остаться, что спрашивали.
- `consent` = 1 проверяется ограничением в БД, `consent_doc_ver` фиксирует версию текста согласия (152-ФЗ).
- `notified_at IS NULL` = уведомление не ушло, cron досылает.
- `branch_id` → `ON DELETE SET NULL`: закрытие филиала не удаляет заявки.

| метод и путь | что делает | кто | вход | выход | сценарий |
| --- | --- | --- | --- | --- | --- |
| `POST /assets/components/fetchit/action.php` (форма `price`) | создать заявку «Узнать стоимость» | любой | name, phone, product_id, submit_token, consent, captcha_token, city? | JSON success/errors | F01 |

| `POST /assets/components/msearch2/action.php` (`search/autocomplete`) | подсказки живого поиска | любой | query (≥ 3 символов) | до 5 товаров + «все результаты» | F04 |
| `POST /assets/components/msearch2/action.php` (`filter/submit`) | фильтр и пагинация раздела | любой | параметры фильтра, page | HTML карточек + счётчик | F01 |
| `GET tel:` / `mailto:` / ссылки на VK, Telegram, OK | связь с филиалом | любой | — | — | F05 |

Хук `nordLead` (FormIt-хук после валидации FetchIt):
1. Проверить SmartCaptcha (серверный запрос к `smartcaptcha.yandexcloud.net/validate`) и поле-ловушку → иначе `status = spam`, без уведомлений.
2. Нормализовать телефон (+7…), обрезать поля по длине.
3. Вставить строку; при дубле `submit_token` вернуть успех, ничего не создавая.
4. Выбрать филиал: по `city_input` → иначе `is_default`.
5. Отправить письмо на email филиала и сообщение в `tg_chat_id`; при успехе поставить `notified_at`.
6. Вернуть успех: на сайте показывается уведомление, в Метрику уходит цель `lead_{type}`.

Входящие вебхуки: нет. Исходящие: Telegram Bot API `sendMessage`, SMTP.

Задачи cron:
| задача | расписание | что делает |
| --- | --- | --- |
| `leads:renotify` | каждые 5 минут | досылает заявки с `notified_at IS NULL` старше 2 минут, не больше 3 попыток |
| `leads:purge` | ежедневно, 03:00 | обнуляет `ip` у заявок старше 30 дней; удаляет заявки старше 3 лет и спам старше 30 дней (сроки согласовать с клиентом и записать в политику) |
| `backup` | ежедневно, 04:00 | дамп БД + `assets/images`, хранить 14 дней на отдельном хранилище в РФ |
| `sitemap` | при сохранении ресурса | плагин pdoSitemap кэширует заново |

## Сложные места

- **Обновление MODX 2 → 3 и miniShop2:** проверить текущую версию на проде. Обновлять копию на staging; после обновления прогнать все URL из sitemap и сравнить коды ответа (200, без 404 и редиректов).
- **SEO и редиректы:** все текущие URL сохраняются. Новые 301 — только для погрузчиков Lonking (переезд в подраздел) и, возможно, `/uslug/spectehnika`. Каноникал на страницах фильтров и пагинации, `noindex` для поиска.
- **Двойная отправка:** `submit_token` + блокировка кнопки на время запроса.
- **Доставка уведомлений:** если Telegram или SMTP недоступны, заявка уже в базе и придёт с `leads:renotify`. Заявка не теряется ни при каком сбое после сохранения.
- **Спам:** SmartCaptcha + ловушка + ограничение частоты: не больше 5 заявок с одного IP за 10 минут (проверка в хуке по `ip` и `created_at`).
- **Часовые пояса:** сервер и БД в UTC. В админке и письмах время показываем по филиалу: Чита и Магадан — UTC+9 и UTC+11, Иркутск — UTC+8. Летнего времени в РФ нет.
- **152-ФЗ:** серверы и почта в РФ, согласие с версией документа, политика на сайте, очистка по сроку. Если сайт ещё не подал уведомление в Роскомнадзор как оператор ПДн — сообщить клиенту.
- **Качество данных:** ошибки в характеристиках (объём двигателя 50.5 л, размер шин) и пустые карточки чинятся вручную, но с правилами в админке: числовые поля через тип `number`, публикация товара без описания и фото запрещена (плагин на `OnBeforeDocFormSave`).
- **Поиск:** морфология mSearch2 + синонимы: «Лонкинг» ↔ «Lonking», «Шанмон» ↔ «SHANMON», «ДГУ» ↔ «дизель-генератор», «фронтальник» ↔ «фронтальный погрузчик».
- **Скорость:** фото в WebP с размерами под сетку, отложенная загрузка, кэш pdoTools; цель — LCP < 2,5 с на мобильном.
- **Пустые разделы:** раздел без товаров не показывать в меню (условие в pdoMenu), а не выводить «Нечего фильтровать».

## Порядок сборки

1. **Вертикальный срез** — карточка товара и заявка по ней работают на новом шаблоне.
   Подготовка: копия прода на staging, обновление до MODX 3 и miniShop2 4, установка таблиц из `schema.sql`.
   Экраны: S05 и M01 на новом шаблоне (шапка и подвал — заготовки).
   Таблицы: `modx_nord_leads`, `modx_nord_branches`.
   Запросы: форма `price` → хук `nordLead` → письмо, Telegram, цель в Метрике.
   Готово, когда тестовая заявка с карточки GROS 388-II приходит в Telegram филиала, а повторный клик не создаёт вторую.
2. **Обязательное (must), по областям:**
   - навигация: шапка, меню каталога (M04), крошки, подвал;
   - каталог: S02, S03, S04 с пагинацией и пустым состоянием, подраздел «Фронтальные погрузчики» и 301;
   - товар: галерея, характеристики, правила заполнения в админке, чистка данных;
   - главная S01;
   - формы M02 и M03, согласие ПДн, уведомления об успехе и ошибке;
   - страницы S06, S07, S10, S13 (из `modx_nord_branches`), S14, S15;
   - SEO: проверка всех URL, редиректы, sitemap, метатеги.
3. **Желательное (should):** фильтр по бренду (починить), живой поиск M05 с синонимами, мобильная нижняя панель, услуги S08, S09 и страницы гарантии, выездного сервиса и доставки, кнопка «Задать вопрос», антиспам, маршрутизация по филиалам, CMP «Заявки».
4. **По возможности (could):** фильтр по характеристикам, FAQ с настоящими вопросами, карта на «Контактах», страница «Логистика», метка «Максимальная комплектация», блок партнёров (после получения прав на логотипы).
5. **Исправления от replica-entrepreneur** — после его запуска (отзывы о дилерах спецтехники и сравнение с конкурентами).
